# Revisión: experto en IA aplicada y sistemas de agentes

## 1. Veredicto en una línea
La idea es viable como **servicio gestionado de un proceso acotado**. No lo es como "repositorio entregable que el cliente mantiene", porque el análisis mezcla la herramienta para construir (Claude Code) con el sistema que tiene que operar en producción.

## 2. Lo que funciona
- **"La IA coordina y el código calcula."** Es el patrón correcto. Los KPI salen de scripts deterministas y el LLM queda para el juicio, la redacción y la extracción. Así se pueden auditar los resultados y bajan los errores numéricos.
- **El conocimiento va separado de los datos.** Postgres, Sheets o el ERP son la fuente de verdad, y el repositorio guarda las instrucciones y los procedimientos. Esto evita el error típico de usar el contexto del modelo como base de datos.
- **Un proceso por intervención, con línea base el día 1.** Es la única forma de que 30 días alcancen y de producir evidencia que se pueda vender.
- **Las skills y los subagentes como unidad reutilizable.** Las skills son hoy un formato abierto (Agent Skills) y MCP es un estándar con amplio soporte. Las "plantillas por proceso" pueden convertirse en un activo real.
- **La gobernanza como argumento de venta** (aprobación humana, registro de acciones). Es lo que compra una empresa mediana, no "magia".

## 3. Lo que no funciona o es riesgoso
- **Confunde la construcción con la operación.** Claude Code es un entorno de desarrollo para una sola persona. Un sistema que escribe por WhatsApp a 20 usuarios, guarda estado y se dispara solo es un **servicio de software**: un proceso con el Agent SDK alojado en un servidor, con autenticación, colas, reintentos, secretos y monitoreo. El entregable no es "un repositorio": es infraestructura en marcha. Eso cambia el Plan A, la estructura de precios y la responsabilidad legal.
- **Cowork o Proyectos como interfaz.** *Supuesto a verificar:* funcionan por usuario, no tienen estado compartido entre varias personas y no envían mensajes por iniciativa propia a terceros. Sirven a quien opera el proceso, no a los usuarios a quienes el sistema "pide información".
- **WhatsApp como interfaz principal subestima el costo.** El propio análisis de Satia lo califica de dificultad alta y no técnica: hace falta un proveedor oficial (BSP), plantillas aprobadas por Meta, la ventana de 24 horas y cuidar la calidad del número. El Agent SDK no resuelve nada de eso.
- **Los conectores MCP para Siigo, Alegra, Contpaqi, Defontana o los bancos locales en general no existen o no están maduros** (*supuesto*: no lo verifiqué uno por uno). Construir y asegurar un solo conector puede consumir buena parte del mes.
- **`evals/` es una carpeta, no una metodología.** Faltan casos de referencia sacados del levantamiento, pruebas de regresión cuando cambia el modelo, trazas y alertas de deriva. Sin eso, el Plan A se degrada sin que nadie lo note.
- **Inyección de instrucciones (prompt injection).** Los agentes leerán correos y mensajes externos y a la vez tendrán herramientas que escriben en el ERP o envían mensajes. Esa combinación es el vector de ataque clásico, y el documento no lo menciona.
- **"Agnóstico, sin dependencia" es parcialmente falso.** El conocimiento es portable, pero el entorno de ejecución (Claude Code, Agent SDK, hooks, subagentes) ata el sistema a Anthropic. Hay que decirlo con honestidad.
- **Precios.** Con USD 500–1.500 al mes de Plan B no se paga a un ingeniero de guardia ni la responsabilidad de operar el sistema. Los costos de tokens de agentes que corren solos pueden superar lo presupuestado si no hay límites.
- **Residencia de datos.** La API corre en EE. UU. Con la LGPD en Brasil o la ley de datos de Colombia, más algunos sectores regulados, puede ser una objeción. *Supuesto:* Bedrock o Vertex ofrecen regiones alternativas, pero hay que confirmar qué modelos están disponibles en cada una.

## 4. Recomendaciones (priorizadas)
1. **Hacer del Plan B (gestionado) el modelo por defecto** y reservar el Plan A para clientes con un equipo técnico propio. Fijar el precio con un piso que cubra la infraestructura, los tokens, las guardias y la propiedad del incidente.
2. **Definir una arquitectura de referencia para operar, no solo para construir:**
    - el Agent SDK en un contenedor propio;
    - un orquestador determinista (n8n, Temporal o cron) para recordatorios y flujos;
    - Postgres como fuente de verdad;
    - trazas con Langfuse o un equivalente.
3. **En el piloto, la interfaz es correo + Sheets/Excel (o Teams/Slack).** WhatsApp entra en una segunda fase, a través de un BSP (Twilio, 360dialog, Gupshup) o de Satia.
4. **Evals como entregable contractual:** de 30 a 50 casos de referencia del proceso, umbrales de aceptación y una ejecución automática antes de cada cambio de modelo o de prompt.
5. **Seguridad desde el diseño:**
    - credenciales MCP de mínimo privilegio y solo lectura por defecto;
    - aprobación humana para toda escritura;
    - aislar el contenido externo;
    - DPA y retención cero (ZDR) cuando aplique.
6. **Elegir el piloto según los conectores disponibles.** La consolidación de reportes en Excel es buena precisamente porque no depende de ERPs locales.
7. **Reformular la promesa:** "un tramo del proceso en producción en 30 días, medido", no "el proceso completo".
8. **Cláusula de propiedad intelectual:** separar el núcleo reutilizable (de Redesign Lab) de los datos y el conocimiento del cliente. Hoy `conocimiento/` mezcla ambos.

## 5. Cómo diferenciarse de soluciones equivalentes
- **Alternativas reales:**
    - plataformas de agentes: Microsoft Copilot Studio (fuerte si el cliente usa M365), Zapier Agents, n8n, Make, Relevance AI, Lindy;
    - conversacional en LatAm: Satia, Treble, Botmaker, Blip, Yalo;
    - integradores: Globant, Softtek, NTT Data, Accenture;
    - y la amenaza más directa: **Claude Enterprise o Cowork con plugins, configurado por el propio cliente** (o por cualquier freelancer).
- **El diferencial no puede ser la tecnología**, porque es un commodity y la replica cualquiera. Tiene que ser:
    - el **rediseño del proceso** antes de automatizarlo;
    - **resultados medidos** (horas, errores, tiempo de ciclo), con una parte del precio ligada al resultado;
    - una **especialización vertical** donde Redesign Lab ya tiene autoridad (reportes de impacto y ESG, consolidación financiera);
    - la **operación gestionada con SLA en español**, que ni las plataformas ni los freelancers ofrecen.
- El catálogo de procesos con evals propios es lo que, con el tiempo, se vuelve difícil de copiar.

## 6. Pregunta clave
**¿Está Redesign Lab dispuesto a ser operador de software (alojamiento, guardias, SLA y responsabilidad cuando un agente envía algo incorrecto a las 3 a. m. del día 45), o solo consultor?** La arquitectura que propone el documento exige lo primero, y el modelo de negocio está pensado para lo segundo.

*Nota:* no hice búsquedas web en esta revisión. El estado de Cowork, de los conectores MCP para ERPs locales y de la disponibilidad regional de modelos está marcado como supuesto y conviene verificarlo.
